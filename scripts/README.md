# Backend Scripts Overview

This folder contains the core backend logic for the Automated Release Notes System. Each script plays a specific role in the release notes generation, summarization, and publishing pipeline.

## Folder Purpose

- Centralizes all backend automation and processing logic.
- Handles data fetching, AI summarization, navigation updates, and intermediate processing for release notes.
- Ensures secure, modular, and maintainable code for the release pipeline.

## Scripts Breakdown

### 1. `fetch_jira.py`
- **Purpose:** Fetches issues from Jira for a specified release tag.
- **Key Features:**
  - Loads Jira credentials from environment variables.
  - Connects to Jira and fetches issues using JQL (`fixVersion = "Release X.Y.Z"`).
  - Categorizes, cleans, and formats issue data.
  - Outputs a Markdown file (`to_llm_vX.Y.Z.md`) in `scripts/processing/` for the next pipeline step.
  - Can also list all available releases (fixVersions) in Jira.

### 2. `summarize_llm.py`
- **Purpose:** Uses OpenAI with a sophisticated two-stage approach to generate comprehensive technical summaries and professional release notes.
- **Key Features:**
  - **Two-Stage Processing:**
    - **Stage 1:** Creates detailed technical summaries of every JIRA issue with comprehensive analysis
    - **Stage 2:** Organizes technical summaries into user-focused, template-compliant release notes
  - Loads OpenAI API key from environment variables.
  - Cleans and chunks input Markdown for efficient LLM processing.
  - Uses advanced prompt engineering for both technical analysis and business communication.
  - Ensures complete coverage of all JIRA issues without filtering.
  - Groups content into structured sections following `templates/release-note-template.md`.
  - Supports `--technical-only` flag for generating just the technical summary.
  - **Outputs:**
    - Technical summary: `docs/releases/vX.Y.Z_technical_summary.md` (Stage 1)
    - Final release notes: `docs/releases/vX.Y.Z.md` (Stage 2)

### 3. `update_nav.py`
- **Purpose:** Automatically updates the `mkdocs.yml` navigation to include new release notes.
- **Key Features:**
  - Scans `docs/releases/` for all release Markdown files.
  - Sorts releases by version (newest first).
  - Updates the "Releases" section in `mkdocs.yml` programmatically.
  - Ensures `releases/index.md` is always at the top.

### 4. `processing/`
- **Purpose:** Workspace for intermediate Markdown files between fetch and summarize steps.
- **Usage:**
  - Stores files like `to_llm_vX.Y.Z.md` generated by `fetch_jira.py` and consumed by `summarize_llm.py`.

## Security & Best Practices
- All secrets are loaded from environment variables (never hardcoded).
- No sensitive data is logged or printed.
- Scripts are modular and follow single-responsibility principles.

## Pipeline Flow

1. **Fetch Jira Issues:** `fetch_jira.py` → `scripts/processing/to_llm_vX.Y.Z.md`
2. **Two-Stage AI Processing:** `summarize_llm.py` → 
   - Stage 1: `docs/releases/vX.Y.Z_technical_summary.md` (comprehensive technical analysis)
   - Stage 2: `docs/releases/vX.Y.Z.md` (formatted release notes)
3. **Update Navigation:** `update_nav.py` → `mkdocs.yml`

## Manual Usage Examples

```bash
# Standard workflow
python fetch_jira.py "Release 2.4.5"
python summarize_llm.py --version 2.4.5
python update_nav.py --version 2.4.5

# Technical review workflow  
python fetch_jira.py "Release 2.4.5"
python summarize_llm.py --version 2.4.5 --technical-only  # Review technical summary first
python summarize_llm.py --version 2.4.5                   # Generate final release notes
python update_nav.py --version 2.4.5
```
